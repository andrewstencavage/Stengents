# Auto-replan benchmark corpus — coverage

Fixture-based corpus for the pure Auto-replan decision function (issue #64,
parent issue #63), mirroring `src/stengents/workout_review/benchmark/` in
shape. Each case is a directory holding two files:

- `input.json` — a self-contained, frozen bundle: `{"strategy": <raw Kiln
  Strategy JSON or null>, "templates": [<raw Kiln Plan Template content>,
  ...], "sessions": [<raw Kiln Session JSON>, ...]}`. The evaluator runs the
  real `decide_auto_replan` against this bundle (`evaluator.run_case`), so a
  case exercises the whole pipeline — selection, draft construction, reorder,
  template-freshness sync — not just one piece of it.
- `expectations.json` — the structured, deterministic assertions:
  `expected_template` (the selected Plan Template's name, or `null`),
  `expected_activate`, `expected_week_start`, `expected_weekdays` (a list of
  `{weekday, name, type}` the draft must match on those days — used both to
  pin an untouched day and to pin a reordered/rest day), `expects_template_update`
  (whether any `TemplateUpdate` should be proposed), and optionally
  `expected_template_update` (exact `prescribedSets` content for one named
  template/weekday/exercise).

All matching is on structured fields only — no prose is generated by this
capability at all (`decide_auto_replan` calls no model), so there is no LLM
rubric layer the way Workout Review defers prose-quality grading to one.

## Case → scenario map

The three scenarios issue #64's acceptance criteria name explicitly, plus a
few more exercising the mechanism further.

| Case id | Scenario | What the expectations pin |
| --- | --- | --- |
| `c01-normal-week` | Normal week (issue #64 AC) | Strategy's `default` rule selects `strength`; the draft matches the template's content on every weekday untouched; no template update. |
| `c02-strategy-directed-deload` | Strategy-directed deload (issue #64 AC) | Four distinct weeks of Session history make a `deload_every_weeks: 4` rule due; `deload` is selected over the `default`, and the draft's Monday reflects the deload template's lighter content. |
| `c03-out-of-order-reorder` | Out-of-order Session reorders the remaining week (issue #64 AC) | Thursday's `Pull Day` is performed on Friday — the issue's own example. Thursday becomes rest, Friday gets the displaced `Pull Day`, Saturday cascades to what was Friday's `Leg Day`, and Sunday (already rest) absorbs what no longer fits. Monday/Wednesday stay untouched. |
| `c04-keyword-template` | Strategy keyword condition selects a named template | A `keyword: travel` rule matches text on the just-finished Session's activity note, selecting `travel` over `default` even though the Session's own name doesn't match anything in the `travel` template (no reorder attempted). |
| `c05-no-strategy-no-activate` | No Strategy / no rule resolves | `strategy` is `null`; no rule names a template, so `expected_template` is `null` and `expected_activate` is `false` — nothing to activate. |
| `c06-template-content-sync` | Template freshness sync (issue #63 user story #4) | The subject Session's performed sets (heavier load) differ from the template's current `prescribedSets` for that exercise; `expects_template_update` is `true` and `expected_template_update` pins the exact revised sets. |

## Draft schema conformance

`c01`/`c02`/`c03`/`c04`/`c06`'s generated drafts (and `c06`'s template
update) were checked directly against the real Kiln zod schemas
(`planDraftInputSchema`/`planTemplateInputSchema`, kiln issue #170's
`mcp/schemas.js`, not yet on kiln's `main`) via `to_kiln_json` — see
`contract.to_kiln_json`'s docstring for the `.optional()`-without-
`.nullable()` gotcha that check surfaced. This isn't wired into the automated
suite (no Kiln checkout is a dependency of this repo's tests), so it is spot
verification, not a regression gate.

## Corpus version

No manual version field, and no content-hash/baseline machinery the way
Workout Review's corpus has: `decide_auto_replan` is fully deterministic (no
model call), so a case either passes or fails on any given corpus content —
there's no model-nondeterminism a hash-stamped baseline exists to track.
